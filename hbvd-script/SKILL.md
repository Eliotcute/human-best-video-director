# 脚本与制作

只把已经确认的选题变成可生产内容。

## 接收任务

读取总入口传入的 `HBVD_TASK_BRIEF` 及已有选题、钩子结论。不得重新询问任务合同中已确认的用户、材料、时长、平台和制作限制。只有事实冲突，或缺口会使脚本不可拍摄且无法安全假设时，才在内部标记 `NEED_CONTEXT`；用户可见回复要直接说明缺少哪项素材、结果或拍摄条件，以及为什么无法继续，不显示内部状态码。选题尚未成立时交回 `$hbvd-topic`，不在本 Skill 中重新发散。

若状态为 `PARTIAL`，只写一个依赖已声明假设的临时版本。完成后把最终结构、证据镜头、制作要求和验证方式追加回任务合同。

## 制作前检查

确认：

- 具体用户与场景
- 本条作品主要使命
- 一句核心表达
- 真实证据、案例、过程或经历
- 内容形式、目标时长和发布平台
- 时间、预算、人员、场景、设备和出镜限制
- 若为Vlog：本期具体问题、目标、选择或变化；只有日程顺序时返回 `$hbvd-intake`

## 编写顺序

1. 先写观众最终得到的变化。
2. 先形成画面顺序，再写必要台词。
3. 开头兑现 `$hbvd-hook` 的承诺；没有单独钩子结果时，按证据、收益、冲突或真实过程建立开头。
4. 每个段落必须增加信息、情绪、故事或证据；删除重复和无效铺垫。
5. 画面负责证明地点、人物、动作、数据和结果；旁白补充背景、因果、感受和判断，不重复描述画面。
6. 结尾交付本期结果；若需要关注，说明真实的后续价值，不制造不会兑现的悬念。

## Vlog主线

先判断是日常型还是挑战型。日常型每期必须有一条叙事主线或一个固定栏目；挑战型必须有真实任务、规则、限制、行动和当期结果。两类都按“问题或目标 → 选择与行动 → 变化或结果”推进，不能把行程、商品、地点和零散片段直接拼成流水账。

- 第一人称不等于只使用POV机位；创作者的任务、选择、行动和反馈必须推动内容。
- 时间先后不是叙事主线；“早上到晚上”只有在围绕同一个本期问题、目标或变化推进时才成立。
- 固定栏目只提供稳定入口，不能替代本期内容；每期仍需一个真实变量、问题、任务、选择或变化。固定开头、固定结尾和日程顺序本身不算主线。
- 本期承诺的结果应尽量在同一条内容中交付，不能只用“下一条揭晓”替代当前回报。
- 结果尚未发生时，只写拍摄任务、规则、关键节点和必须记录的证据；不得预写现场对话、反差、反转、失败或结果。
- 不得为了制造转折，临时增加用户未提出的隐藏规则、不向参与者说明的测试条件或事先安排的反应。
- 拍摄完成后，从真实素材中确定转折和结论；真实结果与原方案不同，以真实结果为准。
- 核心结果或现场反应尚未发生时，将交付明确标为“拍摄方案”，不得称为可直接发布的成片稿。

## 生产约束

- 不出镜：优先使用真实现场、手部、录屏、资料、产品过程、旁白或字幕；同时说明信任建立会依赖哪些证据。
- 素材不足：列出必须补拍的素材；不能用装饰镜头冒充证据。
- 历史素材缺失：使用明确的意象或今日口述，不冒充历史现场。
- 低产能：压缩场景、人物和后期复杂度，优先可重复模板。
- 无真实案例：不得写结果证明型脚本，可改成过程、判断或公开实验。

## 输出合同

默认只给一个可执行版本：

```text
任务对齐：本次目标、交付范围、关键限制
编导判断：用户、使命、核心表达
标题与封面：
一句话承诺：
脚本状态：拍摄方案 / 成片稿
若为Vlog：类型、主线或固定栏目、本期结果
本期具体问题、目标、选择或变化：
结构：按时间或图文页拆分
完整口播或页面文案：
画面与声音分工：
必须拍到的证据镜头：
可替代素材：
拍摄清单：人物、场景、道具、声音
制作复杂度：低 / 中 / 高，并说明原因
真实性与合规风险：
结尾与后续价值：
发布后验证：
```

用户只要结构时不强行写逐字稿；用户明确要可直接念的文案时，提供自然口语版本。
